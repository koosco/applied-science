# 학습 시각자료 컨벤션

학습 문서에서 그래프와 도식을 **정확하고 일관되게 추가·수정·검증**하기 위한 규칙입니다. 학습 설명은 [writing.md](writing.md), 실행 가능한 시뮬레이터는 [experiments.md](experiments.md)도 함께 따릅니다.

## 무엇을 시각화할 것인가

- **그래프:** 극한·연속, 함수의 모양, 접선, 극값, 부호 있는 넓이, 시간에 따른 물리량 등 좌표로 관계를 설명할 때 사용합니다.
- **도식:** 합성함수·치환·부분적분, 신호와 계산의 흐름, 기하학적 가정 등 좌표보다 구조가 중요할 때 사용합니다.
- **인터랙티브 시뮬레이터:** 사용자가 입력·시간·매개변수를 바꿔 관찰해야 할 때 사용합니다. 정적 그림과 역할이 다르므로 기존 시뮬레이터는 유지합니다.
- 설명에 도움이 되지 않는 그림은 억지로 넣지 않습니다. 기본은 **핵심 개념당 의미 있는 그림 1개**이고 서로 다른 판단에 꼭 필요할 때만 추가합니다. 개요 페이지에는 필요하면 학습 흐름도를 둡니다.

## 파일 위치와 재현 가능성

`docs/assets/figures/<분야>/<단원>/<설명적인-이름>.svg`에 저장합니다. 폴더와 파일명은 소문자 `kebab-case`를 사용합니다.

```text
docs/
├── mathematics/calculus/definite-integrals/riemann-sums.md
└── assets/figures/calculus/definite-integrals/riemann-left-rectangles.svg
```

- **SVG가 배포·수정의 원본 파일**입니다. 동일한 도형을 여러 문서가 공유할 때는 조건·변수·단위가 정말 같을 때만 같은 SVG를 재사용합니다.
- 수치 그래프가 복잡하여 코드로 생성한다면 생성 코드를 `scripts/figures/` 등에 저장하고, 입력 매개변수·축 범위·실행 방법을 명시합니다. 같은 입력에서 같은 SVG를 재생성할 수 있어야 합니다. 단순 SVG를 위해 불필요한 생성기나 패키지를 새로 도입하지 않습니다.
- 기존에 작성한 SVG는 일괄 재생성하지 않습니다. 변경할 때 해당 SVG와 설명이 일치하는지 확인하고, 원본 계산이 필요한 경우 생성 스크립트를 함께 추가합니다.
- 생성한 그림을 사용하지 않게 되면 해당 SVG를 정리합니다. 문서 변경과 그림 변경을 **같은 커밋**에 담습니다.

## 내용과 표현 기준

1. **수학적 정확성:** 본문과 그림의 함수식, 정의역, 매개변수, 축 방향, 구간, 경계, 미분·적분의 부호, 점의 좌표를 일치시킵니다. 별도 예시면 반드시 *설명용 예시*라고 밝힙니다.
2. **축과 단위:** 좌표 그래프에는 축의 물리량·단위·유효한 눈금을 표시합니다. 단위가 다른 물리량은 별도 패널로 나타내거나 서로 다른 축임을 분명히 합니다.
3. **오해 방지:** 연속/불연속은 채운 점·빈 점, 국소/전체 극값은 적절한 범위, 적분은 양·음 영역, 근사와 해석적 해는 선 스타일/범례 등으로 구분합니다. 실제 측정과 가상 모델도 명확히 구분합니다.
4. **읽기와 접근성:** `viewBox`를 사용해 크기가 달라도 선명하게 보이는 SVG로 만듭니다. 주요 텍스트가 휴대전화 화면에서도 읽히는지 확인합니다. 색깔 하나만으로 의미를 구분하지 않고 위치·선·기호·범례를 함께 사용합니다.
5. **독립형 파일:** SVG 루트에 `xmlns`, `role="img"`, 고유한 `<title id="...">`·`<desc id="...">`, 둘을 가리키는 `aria-labelledby`를 넣습니다. 외부 스크립트·외부 이미지·인라인 이벤트 핸들러를 넣지 않습니다.

## Markdown에 연결하는 방법

그림은 **관련 개념을 설명한 직후**에 둡니다. 가능한 한 이미지를 별도 줄에 쓰고, 이미지 아래에 *무엇을 관찰해야 하는지* 한두 문장의 캡션을 둡니다. 대체 텍스트는 그래프가 보이지 않아도 중요한 관계를 알 수 있도록 구체적으로 적습니다.

```markdown
## 그래프로 이해하기

![속도 함수가 증가하고 리만 합 직사각형이 이를 아래에서 근사하는 그림](../../../assets/figures/calculus/definite-integrals/riemann-left-rectangles.svg)

*좌측 합은 6m, 실제 적분값은 8m입니다. 구간을 더 나누면 차이가 줄어듭니다.*
```

상대경로는 **문서가 위치한 디렉터리 기준**으로 작성합니다. `docs/` 바깥의 파일을 링크하거나 원격 이미지·캐시용 쿼리 파라미터에 의존하지 않습니다. SVG에 맞는 설명을 적는 것이 목적이므로 모든 문서에 제목 `## 그래프로 이해하기`를 강제하지는 않습니다.

## 검증과 리뷰

저장소 루트에서 아래 명령을 실행합니다.

```sh
python scripts/validate_figures.py
python -m unittest discover -s tests -p 'test_figure_conventions.py'
python -m mkdocs build --strict
```

- **자동 검사:** 이미지의 상대경로와 실제 파일 존재 여부, 비어 있지 않은 대체 텍스트·그림 캡션, SVG의 XML·접근성 메타데이터, 사용하지 않는 SVG, 파일명 규칙을 확인합니다. CI에서는 `main` 배포와 PR에 연결합니다.
- **사람의 검토:** 그래프의 실제 좌표와 수학적 계산이 맞는지, 물리 단위·조건이 올바른지, 휴대전화와 다크 모드에서 이해 가능한지, 연관된 시뮬레이터가 이전처럼 동작하는지를 확인합니다. **자동 검사는 수학적 정확성이나 실제 렌더링을 증명하지 않습니다.**

작업 순서는 (1) 기존 문서·그림 확인 → (2) 그래프/도식/시뮬레이터 판단 → (3) SVG 작성과 수치 검산 → (4) Markdown 삽입과 해석 작성 → (5) 위 검사 및 화면 확인 → (6) 변경 사항을 함께 커밋하는 흐름입니다.
